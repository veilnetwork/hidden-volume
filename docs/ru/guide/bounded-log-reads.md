# Ограниченное чтение точных ID журнала

`Space::read_log_groups`, sync/async single-space и явный multi-space
методы FFI, а также Dart sync/async facades читают точные ID без сканирования диапазона.
Каждая группа объединяет payload в порядке запроса, включая повторы, со своим
лимитом байтов. На вызов допускается восемь групп и 64 записи суммарно;
пустая группа возвращает пустые bytes.

Отсутствующая или слишком большая запись возвращает `None`/`null` для всего
вызова до чтения следующего запрошенного ID. Ошибки структуры/аутентификации
передаются, как при одиночном чтении. Частичные результаты и декодированные
batches очищаются при ошибке/вытеснении. Только успешный результат становится
plaintext, принадлежащим вызывающему коду.

Между группами одного вызова используется существующий decoded-batch cache
с лимитами 64 entries / 8 МиБ. Каждая ссылка индекса проверяется по digest
настоящего сжатого payload, в том числе cache hit после legacy ссылки без
хеша. По завершении вызова cache удаляется; следующий вызов снова читает
текущие index/data. Кэша маршрутизации, авторизации или данных между вызовами
нет. Выход дополнительно ограничен 64 максимальными payload записи;
прежний предел декодирования одного batch действует независимо.

Добавочный API доступен у sync/async single-space и явного multi-space
handle. Async-запрос владеет вложенными списками ID до dispatch; multi-space
сохраняет явный выбор space. Интерфейсы прежних scalar/range методов прежние.
Dart binding и native-библиотека должны совпадать: UniFFI checksum gate
отклоняет старую библиотеку без нового метода. Перед распространением нужно
пересобрать native artifact вместе с binding. Формат контейнера, криптография
и сетевой протокол не меняются.

Выходные buffers заранее резервируют только ограниченную ёмкость запроса
(суммарно не более 64 максимальных payload), чтобы reallocation Vec не
освобождала промежуточные plaintext-копии до zeroization. Неограниченный
байтовый лимит вызывающего не становится размером выделения памяти.
